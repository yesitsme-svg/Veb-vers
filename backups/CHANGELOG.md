# История правок Motion Grid

Каждая правка = один файл-снапшот + один git-коммит.
Откатиться можно двумя способами:

**Просто файлом** — скопировать нужный снапшот поверх `index.html`:
```
cp backups/000-baseline.html index.html
```

**Через git** (сохраняет всю историю):
```
git log --oneline          # список правок
git checkout <hash> -- index.html
```

## 000 — baseline
Слепок из `MotionGridforAnton.zip` (коммит `0f078cf`, ветка `main`).
25 темплейтов, 4 easing-кривые, 20 демо-картинок. Ничего не менялось.

## 001 — новый пресет «Push Stack» (категория Cards)
Референс: Savee Marketplace «Stack 07».

Глубокий уходящий вверх стек. Каждый бит импульс стартует с **задней** карточки и
идёт вперёд по одной (задержка 0.12 с на слот), поэтому промежутки сжимаются как в
домино; дойдя до передней, выталкивает её вниз за кадр.

Замеры с референса: масштабы слотов 1 / 0.75 / 0.50 / 0.34 / 0.20 легли на
`z(s) = 0.165·camZ·s·(1+s)` — шаг по глубине ускоряется, ближние карточки остаются
крупными, дальние схлопываются в точку схода (+0.32 высоты кадра). Бит 1.5 с:
движение ~0.9 с, покой ~0.6 с.

Подъём слота задан в высотах **карточки**, а не кадра — просвет между слотами
одинаков и на портретных, и на ландшафтных исходниках.

Добавлено:
- движок `pushStack` в конце `SCENES`;
- запись `push-stack` в `TEMPLATES` после `showcase`;
- `'pushStack'` в `LIVE_SPACE` (спейсинг живой, без ребилда) и в `FROZEN_SPAN_FADE`
  (колода рециклит карточки, замороженный диапазон убирает скачок прозрачности).

Старое не тронуто: в диффе всего две изменённые строки — те самые два Set,
остальные 69 строк чистая вставка. Все 24 темплейта строятся, превью не пустые,
шов петли идентичен, экспорт WebM проходит.

## 002 — Push Stack: плотнее, плавнее, медленнее
Правки только внутри пресета `push-stack`, чужой код не тронут.

**Плотнее.** Дефолтный спейсинг 1.0 → **0.8**.

**Медленнее ~10%.** Бит 1.5 → **1.65 с** (`dur` .8→.88, `hold` .7→.77). Слайдер
Speed остался на 1.00 — замедление зашито в сам пресет.

**Плавнее.** Топорность была измерима: профиль экранного движения шёл пилой
`66-58-99-63-141-89-55` (каждая карточка отрабатывала отдельным щелчком), а
последние 0.4 с бита были полностью заморожены. Четыре причины и что сделано:

1. Дефолтный easing `Ease Out` → **`Smooth`**. Ease Out укладывает 90% хода в
   первую треть длительности, из-за чего удары не сливались. Smooth размазывает
   ход по всей длительности — профиль стал одним чистым горбом
   `3-4-13-52-79-195-251-217-156-103` без единого зубца. Ease Out и Snappy
   остались доступны в чипах.
2. Задержка волны распределяется по **степенной кривой** (`wave:1.6`), а не
   линейно по слотам. Из-за перспективы задняя карточка на экране почти не
   двигается, а передняя проходит весь кадр; при равном шаге первая половина
   бита выглядела мёртвой. Теперь задние отрабатывают плотной пачкой, передним
   даётся простор.
3. Выброс передней карточки растянут `dur*0.55` → **`dur*0.78`**. Это самый
   крупный объект в кадре, короткое падение собирало всё движение бита в один
   комок и оставляло мёртвый хвост.
4. Добавлено «дыхание» на весь бит (~1.8% высоты карточки), чтобы колода не
   вставала намертво в паузе — тот же приём, что в Stack Reveal и Shuffle.

Порядок импульса (с задней вперёд) сохранён — проверено по контактному листу.
Регрессия: все 24 темплейта строятся, превью не пустое, шов петли идентичен,
Reset возвращает 0.80/Smooth, все 5 форматов кадра и весь диапазон спейсинга
0.5–2.8 держат 7 карточек, консоль чистая.

## 003 — новый пресет «Push Cascade» (категория Cards)
Референс: скрин Rico «Stack 01» — черепичный ряд по диагонали.

Тот же домино-импульс, что в Push Stack, но повёрнутый на бок: карточки идут
диагональю сверху-слева вниз-направо, импульс стартует с дальней верхней-левой
и бежит **слева направо**, каждая толкает следующую, ведущая вылетает за
нижний-правый угол. Плоский ряд, без перспективы — глубина читается наложением.

Замеры с референса (кадр 1041×711): шаг между карточками 136×92 px = **13% по
каждой оси кадра**, то есть ряд идёт ровно по диагонали кадра, ~7.7 штук
поперёк в любом формате. Карточка ≈0.19 диагонали кадра.

Решения:
- размер карточки задан **постоянной площадью** (`h = CH/√asp`), а не постоянной
  высотой — иначе 16:9 и 4:5 в одном ряду скакали бы по величине;
- ряд смещён на 0.7 слота вверх-влево (`bias`), иначе центр ведущей карточки
  попадает точно в угол кадра и видна только её четверть;
- карточки входят и рециклятся за кадром, поэтому фейд для шва не нужен вообще;
- под наклоном ряд поднимается в пологую лесенку (`stepZ*tiltR`) — параллельные
  плоскости не пересекаются, порядок отрисовки не мерцает (приём из Cascade).

Добавлено: движок `pushCascade`, запись `push-cascade` в `TEMPLATES` после
Push Stack, `'pushCascade'` в `LIVE_SPACE` и в `FLAT_ROT_FADE` (плоский в покое,
Card Fade разблокируется при наклоне; попадает и в `FROZEN_SPAN_FADE`).

### Заодно исправлено в обоих пресетах
**Петля была втрое длиннее нужного.** `n` добивается до кратного числу картинок,
чтобы заполнить ряд, но картинка при этом повторяется каждые **N0** битов, а не
`n`. При 3 картинках экспорт содержал одно и то же трижды: 4.95 с вместо 1.65 с.
Теперь `loopSeconds = cyc*N0`.

**Порог видимости отсекал на слот раньше.** Карточка на слот дальше рубежа всё
ещё въезжает в зону видимости за бит — отсечение ровно по границе роняло её.
Расширено на один слот в обоих движках.

Проверка: шов петли **пиксельно идентичен** для обоих пресетов при 1,2,3,4,5,6,
8,9,20 картинках и на пяти смещениях внутри бита. Все 25 темплейтов строятся,
превью не пустые, экспорт WebM проходит, консоль чистая.

## 004 — новый пресет «Spinner» (категория 3D Space)
Референс: 6TM Magazine «3D Showcase 01 — Spinner».

Карточки посажены **радиальными лопастями на вертикальное кольцо**, как лопатки
на гребном колесе. Ключ — угол лопасти: карточка развёрнута на 90° от
касательной к кольцу, то есть лежит в плоскости, проходящей через ось колеса,
а не обёрнута по ободу. Отсюда картинка референса: карточка в **передней**
точке кольца стоит ребром и читается тонкой полоской поперёк центра кадра,
**верхняя** смотрит на зрителя лицом, **нижняя** — тоже лицом, но вверх ногами,
потому что проехала дальше вертикали.

Обычное касательное кольцо ставит лицевую карточку в переднюю точку, ровно в
центр кадра, а наклонённые — сверху и снизу. Это симметричный барабан, и это
не то.

Лопасти лежат в плоскостях, проходящих через одну общую ось, поэтому
задеть друг друга они могут только дотянувшись до неё. Радиус с полом в 0.55
высоты карточки гарантирует, что не дотянутся — при любом числе картинок и на
всём диапазоне Spacing (замерено: зазор от внутренней кромки до оси 0.079 при
Spacing 0.5 и 1.86 при 2.8).

Петля `cyc·N`: после N битов карточка i встаёт на место карточки i+N, обе
несут картинку `i mod N`.

### Три захода до этого — что было не так
1. **Барабан с потолком радиуса.** Карточки на кольце расходятся только при
   `R ≥ H / (2·sin(π/n))`; любой потолок ниже — гарантированное пересечение.
   На 20 картинках хорда падала до 0.30 высоты карточки: соседи входили друг в
   друга на 70%. Отсюда протыкание и лаги от overdraw.
2. **Честное касательное кольцо.** Пересечений нет, но веер равен `2π/n` — от
   60° при шести картинках до 18° при двадцати, и карточки становятся плоскими.
3. **Вертикальный конвейер.** Структура «лицом → ребром → вверх ногами»
   воспроизводилась, но это была имитация: поворот и позиция задавались
   независимо, тогда как в оригинале обоими управляет одна угловая координата
   на кольце.

Диff против 003: **40 добавленных строк, ноль изменённых.** Общий код не тронут.

Проверка: шов петли пиксельно идентичен при 1–20 картинках на шести смещениях
внутри бита; все 26 темплейтов строятся, превью не пустые; все 5 форматов кадра
держат 8 карточек; лопасти не достают до оси на всём диапазоне Spacing; экспорт
WebM проходит.

## 005 — Card Fade в Push Stack; Spinner: 10 лопастей и фикс флика при наклоне
Три правки по фидбеку с первого просмотра (2 сентября).

### Push Stack: дальние карточки теперь уходят в 0 по Card Fade
Замер до правки: при Card Fade 100% самая дальняя ПОЛНАЯ карточка (слот 5)
глохла только до uFade 0.15 и дальше не темнела. Причина: общий механизм
(applyDepthFade) меряет диапазон глубины по «видимым» карточкам, а в Push Stack
в него попадают карточки-призраки разгонной зоны (слоты 5–7, альфа ≈ 0, но флаг
visible ещё стоит) — они растягивают диапазон, и читаемым карточкам достаются
только первые ~70% кривой.

Решение: Push Stack ведёт uFade сам, по слотовой координате `s` (как это уже
делает Spiral): передняя карточка всегда 1, карточка на последнем полном слоте
(VIS=5) при 100% уходит ровно в 0, кривая та же, что в общем механизме
(`1-f·(1-(1-t)^(1+f·0.5))`, t=s/VIS). Из applyDepthFade сцена исключена
(ранний return рядом со spiral), из FROZEN_SPAN_FADE убрана. Бонус: фейд больше
не зависит от того, в какой фазе бита заморозился диапазон — только от слота.

Замер после: front uFade=1, слот 5 → 0.000 при 100%, в любой фазе бита;
при 0% все uFade=1.

### Spinner: лопастей вдвое меньше по дефолту
Дефолтная колода — 20 картинок → 20 лопастей, колесо читалось сплошным диском.
В пресет добавлен потолок `maxB:10`: лопастей не больше 10, а лишние картинки
подменяются на лопасти в момент прохода ЗАДНЕЙ точки колеса — там лопасть
стоит ровно ребром (нулевая площадь) и рисуется позади всего, подмена не видна.

Какую картинку несёт лопасть, решает её ближайший бит прибытия на фронт
(фронт показывает картинку −c mod N в бит c): `s = (i − nb·round((b+i)/nb)) mod N`.
Так фронт по-прежнему получает новую картинку каждый бит, а петля сходится за
`cyc·N` при ЛЮБОМ N — включая некратные числу лопастей (первый вариант формулы
через счётчик задних проходов ломал шов при N=13: за N битов колесо
проворачивалось на нецелое число оборотов, и лопасть в той же точке несла не
ту картинку; проверка diff=2.28 млн px это поймала). Без капа (nb кратно N)
формула вырождается в прежнее `i mod N` — поведение не меняется.

При смене картинки лопасть подхватывает и её аспект: `scale.x` + uniform
`aspect` (приём из Flicker), микс форматов не ломает геометрию.

### Spinner: флик при вращении — найдено и починено
Воспроизведено покадрово (браузерный стенд, дифф соседних кадров с шагом 4 мс):
на дефолте сцена непрерывна по всему обороту (фон ~800 px/кадр, пиков нет),
но при Rotate X=25° — разовый скачок 13 599 px за 4 мс: карточка резко
перепрыгивает вперёд/назад. Это и есть флик.

Причина: порядок отрисовки задавался локальным z (`renderOrder=position.z`),
а наклон по X орбитит КАМЕРУ вверх — правильный порядок лопастей зависит от
угла камеры вокруг оси колеса, и z-порядок переключал лопасти не в скрытой
точке, а на виду. (По Y флика нет: камера остаётся в плоскости z, порядок
совпадает — потому наклон вправо-влево выглядел нормально.)

Решение: Spinner добавлен к ring/globe в вызов sortCardsByDepth() (сортировка
по реальному расстоянию до камеры, уже есть в проекте). Для лопастей на
окружности порядок по расстоянию = точный угловой порядок от камеры при любом
наклоне. Своя строчка renderOrder из движка убрана.

Замер после: пиков нет при rotX=25°, rotX=−35°, rotY=30° и на дефолте.

### Регрессия
Все 26 темплейтов строятся, превью не пустые; шов петли Spinner пиксельно
идентичен (maxd=0) при 3, 13 и 20 картинках, включая миксованные аспекты;
Push Stack при Card Fade 0% не изменился ни на пиксель против прежнего
поведения (все uFade=1).

## 006 — Spinner: флик при Rotate X — протыкание лопастей на большом Card Size
Флик из 005 ушёл не весь: пользователь видел его и после фикса сортировки.
Воспроизведено при Card Size ≥ ~1.2: Card Size — ЖИВОЙ пер-карточный масштаб
(uSize, без ребилда), и выросшая лопасть дотягивается внутренней кромкой до
оси колеса, где сходятся плоскости всех лопастей. Дальше оси плоскости
пересекаются физически — painter's order это не разрешит в принципе, и швы
пересечений ползут по карточкам при вращении. Виднее всего под Rotate X:
камера смотрит прямо в горло колеса. Подтверждено кадром: при size 1.4 кромки
соседних лопастей торчали сквозь карточки.

Гарантия 004 «радиус с полом 0.55 высоты карточки» считалась от высоты при
size=1 и живой рост карточки не учитывала.

Решение: пол радиуса пересчитывается каждый кадр от ЖИВОГО размера —
`R_live = max(H·size·0.55, R)`. Карточки растут → колесо дышит наружу,
кромки не достают до оси ни при каком размере. На дефолтном size=1 поведение
не меняется (пол не активен).

Замер после: протыкания нет визуально (кадр size 1.4 / rotX 25°), диффы без
пиков на size 1.4/rotX 25, size 2.0/rotX −40, size 1.6/rotY 30/spacing 0.5.
Регрессия 005 повторена целиком: 26 темплейтов строятся, шов петли Spinner
пиксельно идентичен при 3/13/20 картинках, Push Stack фейд на месте.

## 007 — Spinner: живой Spacing, подмена картинок с учётом наклона камеры
Два замечания с просмотра 006.

**Spacing не был живым.** Spinner не входил в LIVE_SPACE, слайдер дёргал полный
ребилд сцены на каждое движение — отсюда лаг и рывки. Теперь радиус считается
каждый кадр от живых значений: `R = max(H·size·0.55, R0·spacing)`, сцена
добавлена в LIVE_SPACE (ребилда нет). Замер: 10 лопастей до и после, радиус
0.87 / 0.95 / 1.89 / 2.65 при spacing 0.5 / 1 / 2 / 2.8 (на 0.5 держит пол
от размера карточки — кромки до оси не достают).

**Подмена картинок под наклоном.** Подмена шла в геометрической задней точке
колеса — она ребро только для камеры в плоскости колеса. Rotate X орбитит
камеру вверх, и «заднее ребро» показывает ей часть лица: смена картинки
становилась видна. Теперь точка подмены — напротив угла самой камеры вокруг
оси колеса (`del = atan2(cam.y, cam.z)·nb/2π` в формуле выбора картинки):
там лопасть ребром для любого наклона. При Rotate Y камера остаётся в
плоскости колеса, сдвиг ноль — как и было.

Проверка: полное покрытие бита шагом 2 мс при rotX ±45°, rotY ±45°, X30+Y30,
X45+size 1.6 — дискретных пиков нет (максимумы = первый кадр после смены
настроек и плавное движение). Шов петли 0 px при rotX 25°, rotY 40°,
spacing 2.2. Все 26 темплейтов строятся.

## 008 — новые пресеты «Push Row» и «Push Column» (категория Cards)
Референсы: два видео с Savee Marketplace («Studio 02»), 864×1080, 30 fps —
горизонтальная лента и её вертикальная версия. Разобраны покадрово (385 и
372 кадров), границы карточек трекались по центральной полосе.

### Что это
Одна лента карточек: Row едет справа налево, Column — снизу вверх. Каждый
бит лента сдвигается ровно на одну карточку + зазор, и следующая карточка
встаёт на якорь. Червяк: первой стартует карточка у ВЫХОДА, каждая
следующая за ней — с задержкой, поэтому зазоры позади лидеров растягиваются
и потом схлопываются обратно. Карточки входят и рециклятся за кадром —
фейд для шва не нужен.

### Замеры референса (Row, горизонталь)
- карточки одной высоты 352 px = **0.326 кадра**, ширина по аспекту (в видео
  1.61 / 1.08 / 0.69 / 0.45 — микс форматов);
- зазор **64 px = 0.182 высоты карточки**, одинаковый везде. «Зазоры 5 px»,
  которые виделись сначала, оказались тёмными панелями ВНУТРИ картинок
  (картинки в референсе анимированные — отсюда же «микродрейф» в покое);

## 010 — новый пресет «Zoom Stack» (категория Cuts)
Референс: полноэкранный «dive-in» 864×1080, 30 fps. Разобран покадрово
(таблица аналитика): каждая новая картинка рождается точкой в центре кадра и,
оставаясь центрированной и осепараллельной, раздувается до полного кадра,
накрывая предыдущую. Предыдущая не двигается — она уже заполнила кадр и лежит
неподвижным фоном, пока её не накроют. Ни фейдов, ни поворотов, ни теней,
ни скруглений, ни параллакса — чистый масштаб.

### Замеры референса
- карточка = уменьшенная копия кадра (аспект = аспект кадра, cover-кроп),
  поэтому в масштабе 1.0 она бесшовно становится фоном; зазоров нет, corner 0;
- размер: старт 0 (точка) → 1.00 кадра; первый видимый кадр уже 0.245;
- бит **0.25 с** (4 карточки/с, старты через ровно 7.5 кадра); рост **0.50 с**
  = 2 бита → в полёте одновременно две: одна доезжает 0.89→1.0, вторая
  взлетает с нуля; покоя внутри бита нет; видно 2–3 карточки;
- профиль **cubic-bezier(0,0,0,1)**, очень крутой ease-out без перелёта
  (0.1→0.446, 0.5→0.890, 0.9→0.997); стаггера/волны нет;
- ширина растущей карточки по кадрам (доля кадра): .245 .447 .574 .671 .744
  .803 .852 .889 .921 .944 .965 .979 .991 .997 1.0. Эта серия — точная
  bezier(0,0,0,1), снятая на полукадрах t=(k−0.5)/30 (период 7.5 кадра →
  половина стартов приходится на середину кадра); проверено численно:
  расхождение ≤ 0.002 по всем 15 точкам;
- петля N × 0.25 с; в референсе ~0.33 с hold на последней (титульной).

### Движок `zoomStack`
- n = N (≥ 3, иначе источники дублируются: фон + доезжающая + растущая должны
  быть разными карточками). Камера z=5, карточка `plane(texAt(i, fr.w/fr.h),
  fr.w, fr.h)` — cover-кроп ровно под аспект кадра (как у сеточных пресетов),
  без полей при любом миксе аспектов; текстуры кешируются по key|aspect.
- Время, не кадры: старт карточки i = i·bit, возраст d = (local − i·bit) mod
  loop; scale = clamp01(easeFn(clamp01(d/dur))) — после 1.0 карточка не растёт.
  `m.scale.set(s,s,1)`, при s=0 карточка невидима (старт с нуля — норма
  референса, s0>0 не подкладываем).
- Карточка прячется, когда СЛЕДУЮЩАЯ доехала до 1.0: d ≥ (bit + dur), для
  последней — (bit + hold + dur). В этот момент она полностью накрыта
  (обе в одной плоскости z=0, одинаковый кадр) → выключение невидимо и в
  покое, и под наклоном.
- renderOrder = loop − d: новейшая сверху, доезжающая под ней, фон ниже
  (depthTest выключен, порядок художника — единственное, что важно).
- Петля loop = n·bit + hold; последняя карточка продолжает расти через шов
  (её d берётся по модулю loop), первая стартует поверх неё. `hold` —
  дополнительная пауза перед рестартом (по умолчанию 0; последняя лежит
  поверх одна bit+hold−dur).
- Никакой прозрачности/uFade: `setCardOpacity(m,1)`.

### Строка TEMPLATES (Cuts, после Flicker)
`{id:'zoom-stack', name:'Zoom Stack', scene:'zoomStack', ease:'Ease Out',
bez:[.005,.02,0,1], noRot:true, noSpace:true, eases:['Ease Out','Smooth'],
P:{dur:.5, bit:.25, hold:0, corner:0}}` — флаги noRot/noSpace как у соседей
Zoom Gallery/Flicker; кастомная кривая через `bez` (механизм с Push Row).
В наборы LIVE_SPACE / SCALE_SPACE / FLAT_ROT_FADE / FROZEN_SPAN_FADE не
входит (плоский, повороты и спейсинг заблокированы — как Zoom Gallery/Flicker).

### Тупик: bez [0,0,0,1] ломает решатель cubicBezier()
Первая сборка с `bez:[0,0,0,1]` (ровно как в референсе) провалила гейт:
pops на каждом старте карточки (1.252/1.504 с, 25–43 тыс. px за 4 мс) —
карточка на первых ~15 мс рисовалась ВО ВЕСЬ КАДР, потом схлопывалась к
~0.4. Причина не в движке: `cubicBezier()` решает x(t)=x Ньютоном со стартом
t=x без запасного метода; при x1=x2=0 кривая x(t)=t³ плоская у нуля, первый
шаг из t=x улетает далеко за 1 (для x=0.004 → t≈83), clamp → t=1 → y=1.
Проверено численно: для x ≤ 0.02 решатель отдаёт 1.000 вместо 0.06–0.36,
94 немонотонных шага на сетке 0.0005.
Решение в патче: ручки чуть сдвинуты — `[.005,.02,0,1]`. Ньютон сходится
(ошибка ≤ 2e-4, монотонно), отклонение от точной bezier(0,0,0,1) ≤ 0.007
по всей кривой, от замеренной серии ≤ 0.005 (перебор сетки x1∈[0..0.05],
y1∈[0..0.15], x2∈[0..0.05] — это лучший сходящийся вариант).
**Общая правка (отдельно, не в этом патче):** запасная бисекция в
`cubicBezier()` после Ньютона — `patches/zoom-stack-cubicBezier-fix.patch`.
Это чинит и редактор Custom-кривой: пользователь, стянувший обе x-ручки в 0,
сейчас получает ту же ломаную. После фикса bez пресета можно вернуть на
`[0,0,0,1]` (проверено численно: с бисекцией ошибка ≤ 2.2e-4 и на [0,0,0,1],
и на четырёх штатных кривых).

### Заодно — общий фикс `cubicBezier()` (решатель кривой)
Ньютон стартовал с t=x без запасного метода: при ручках x1=x2=0 (кривая

Проверка на основной ветке: `verify.js zoom-stack --tilt --smoke` → VERIFY OK,

## 011 — новый пресет «Timeline Drift» (категория Grids & Scrolls)
Референс refC («The Recap 03»), 864×1080 @30 fps, 539 кадров = 18.0 с, таблица
аналитика в `tools/out/ref-refC/ANALYSIS.md` (`analyze-ref.py` тут бесполезен:
покоя и битов в ролике нет, всё линейно).

### Что это
Бесконечный горизонтальный таймлайн: на чёрном фоне разбросанные (не по сетке)
карточки трёх слоёв глубины плывут влево на трёх параллакс-скоростях, под ними
в противоположную сторону (вправо) едет фоновая сетка из 12 волосяных вертикалей,
в центре неподвижный заголовок; NEAR-слой проходит перед заголовком, MID/FAR — за.
Ни битов, ни easing-а, ни фейда — чистая линейка, петля 18 с.

### Замеры референса → параметры движка
| | референс | движок |
|---|---|---|
| Скорость MID | 0.188 W/s | `P.speed` 0.188 W/s |
| FAR / NEAR | ×0.89 / ×1.08 | ×0.89 / ×1.08 |
| Сетка | 0.128 W/s, ×0.68, противоположный знак, шаг 0.192 W, 12 колонок = петля | `gridK` 0.68, `cols` 12, шаг = v·loop/12 = 0.1918 W |
| Петля | 18.0 с, слои проходят 3.01 / 3.38 / 3.66 W | `loop` 18; длина мира слоя = v_слоя·loop |
| Размеры карточек | FAR 0.08–0.10 H, MID 0.115–0.13 H, NEAR 0.145–0.18 H, ±20 % | 0.09 / 0.125 / 0.17 H × (0.8…1.2), seed-рандом |
| Аспект | по картинке (contain) | `entryForSlot` — своя текстура без кропа |
| Зазоры по x в слое | 0.02–0.3 W, без перекрытий | rejection-sampling: зазор ≥0.02 W по x и ≥0.03 H по y внутри слоя; между слоями перекрытие допустимо |
| Заголовок | cap 0.065 H, ширина 0.78 W, центр кадра, между MID и NEAR | canvas-текстура, cap 0.065 H, но не шире 0.78 W; renderOrder между MID и NEAR |
| Линия | 1 px, RGB(47,47,47) | тонкий квад 1.15 px при H=1080 (≈2.3 px при 2k-экспорте), цвет = фон + 18.5 % к контрастному тону (на чёрном ровно 47) |

### Как сделано
Движок `timelineDrift` (конец `SCENES`, только вставка), строка `TEMPLATES`
после `grid-drift`, членство в `LIVE_SPACE` и `FLAT_ROT_FADE` (→ и в
`FROZEN_SPAN_FADE`). Три слоя: у каждого своя длина мира `len = k·v·loop`,
карточки раскладываются по этой длине и оборачиваются по модулю; фаза считается
через `u = frac(T/loop)`, поэтому кадры t и t+loop совпадают побитно. Сетка —
один меш из ~15 квадов, сдвигается на `frac(u·12)·pitch`. Раскладка: seed
`mulberry32(29)`, x стратифицирован по слоту (нет дыр и кучек), y случайный по
всей высоте (карточки заходят за края, как в референсе), 60 попыток на
карточку. Число карточек: FAR 2.6, MID 2.8, NEAR 2.2 на ширину кадра
(масштабируется под аспект кадра относительно 4:5) → 24 карточки при 3:4,
25 при 4:5; `minN` 12.

**Первый пресет с текстом.** Заголовок — плоскость с canvas-текстурой (текст из
`P.title`, дефолт 'THE RECAP 03', белый, `500 'Euclid Circular B', Inter, …` —
Euclid уже грузится сайтом с CDN; если шрифт ещё не декодирован при первой
сборке, `document.fonts.load` один раз дёргает `scheduleRebuild`). Цвет
заголовка и линий следует за фоном (белый на тёмном, чёрный на светлом). UI не
добавлялся. Препятствие в проекте: `forEachCard` считает карточкой любой меш с
`uFade`, а `pickCard` — любую `PlaneGeometry`. Поэтому заголовок и сетка
сделаны на обычном `MeshBasicMaterial`, геометрия заголовка скопирована в
`BufferGeometry`, у обоих `raycast=()=>{}` → их не видят фейд, Card Size,
клик-замена, dump и смоук. Текстура заголовка освобождается по событию
`dispose` материала (общий `rebuild` чистит только `uniforms.map`).

**Spacing — живой, как у Rows/`floating`.** Плотность скаттера привязана к
длине мира, а длина мира — к скорости и петле (`len = v·loop`), поэтому
«раздвинуть» карточки без изменения петли можно только масштабируя весь мир:
`x·sp`, `y·sp`, `len·sp` — ровно то, что `SCALE_SPACE` делает для `floating`
(позиции ×spacing от центра), только внутри `update()` (LIVE_SPACE), чтобы
петля и сетка не зависели от слайдера. Побочный эффект тот же, что у Rows:
скорость растёт вместе со spacing (мир длиннее, петля та же); сетка и заголовок
слайдер не трогает. Ниже 1 — карточки сгущаются к центральной линии и
перекрываются (mush), как у `floating`.

### Тупики / оговорки
- Слои по z разносить нельзя: при камере z=5 слой на z=−0.7 уменьшился бы в
  перспективе на 12 % и поменял бы видимую скорость. Все слои копланарны (z=0),
  порядок — только renderOrder; глубина появляется лишь под наклоном
  (FLAT_ROT_FADE).
- WebGL не рисует линии толще 1 px — сетка сделана квадами, иначе на 2k
  линия остаётся 1 px и мерцает.
- Подписи карточек и месяцы (часть референса) не делались — механика работает

## NNN — новый пресет «Fan Deck» (категория Cards, после Shuffle)
Референс: refA (`tools/out/ref-refA/`), 722×456 (16:10), 526 кадров @30 fps, 9 карточек,
петля ровно 9 битов. `analyze-ref.py` на нём не работает (светлый фон) — числа сняты
отдельным трекером по цвету/рёбрам (`ANALYSIS.md` там же).

### Что это
Плоский 2D-веер из 5 квадратных карточек: каждая следующая лежит ПОД предыдущей и
повёрнута на +10° по часовой вокруг общей точки чуть ниже нижнего ребра верхней (0°, 10°,
20°, 30°, 40°). Каждый бит верхняя карточка качается влево-вниз, как маятник вокруг точки
далеко под кадром (−32°, к концу +10 % размера), а вся колода одновременно, без волны,
поворачивается на −10° — каждая занимает слот предыдущей. Новая карточка сзади не
появляется — она уже лежит ровно на 40° под пятой и просто открывается, когда пятая
уезжает вперёд. Ни фейда, ни глубины, ни параллакса.

### Замеры референса (S = сторона карточки = 319 px = 0.70 H)
- верхняя карточка (покой): 0°, центр (0.364 W, 0.451 H) = (−0.31 S, +0.07 S) от центра кадра;
- слоты 0…4: 0 / 10.0 / 19.2 / 30.1 / 40.0° → **шаг 10°**; общий пивот **(+0.13 S, +0.86 S)**
  вниз от центра верхней (0.36 S ниже её нижнего ребра); ступенька правого ребра ≈ 0.18 S;
  размер по глубине не меняется; скругление ≈ 3 % стороны;
- бит **58.4 к = 1.947 с**; сдвиг колоды 50 % на +16 к, 90 % на +29 к, 99 % на +42 к,
  все слоты синхронно (задержка волны 0); пауза ≈ 0.3 с при dur 1.65 с;
- вылет: поворот **−32°** вокруг пивота **(−0.22 S, +2.74 S)** от центра карточки (то же,
  что rotation −32° + перенос центра на (−1.49 S, +0.30 S)), **28 к = 0.93 с**,
  ease-in-out (.42,0,.58,1); масштаб 1.013 @ p=.29 … 1.077 @ .89 → **1 + 0.10·p²**;
- в референсе на p=1 правый нижний угол улетающей карточки ещё виден у левого края
  (кадры r081–r089), совсем уходит между f88 и f99 — карточка продолжает медленно
  выезжать после конца кривой.

### Как сделано
Движок `fanDeck` в `SCENES` (в конце), запись `fan-deck` в `TEMPLATES` сразу после
`shuffle`, членство в `LIVE_SPACE` и `FLAT_ROT_FADE` (плоский в покое → фейд разблокирован
только под наклоном; через FLAT_ROT_FADE попадает и в `FROZEN_SPAN_FADE`).

- **Квадрат** S = min(0.70 H, 0.50 W) — на 16:10/16:9 ровно 0.70 H, на портретных кадрах
  упирается в ширину (3:4 → 0.375 H, веер целиком в кадре). Картинки cover-crop в квадрат
  через `texAt(i,1)` (как у гридов): веер держится на ступеньках ОДИНАКОВЫХ квадратов,
  contain-fit дал бы полосы фона внутри карточки, а нативный аспект (как в Stack Reveal)
  ломает ступеньку. Card Size — общий `uSize` (сторона растёт, раскладка стоит).
- **Слот = поворот вокруг общего пивота**: `place()` крутит центр верхней карточки вокруг
  пивота на `−s·step` (three.js y вверх, поэтому знак экранного «по часовой» инвертирован)
  и ставит `rotation.z` на тот же угол. Положение непрерывное по `s = b − e`, renderOrder
  `n − s` (непрерывный — как в Stack Reveal, целочисленный менял порядок соседей).
- **Задний слот — жёсткий стоп**: угол берётся от `min(s, VIS−1)`, поэтому карточка со
  слота VIS всю дорогу лежит ровно на 40° под уходящей вперёд, и её открывает движение
  пятой, а не собственный сдвиг. Карточки глубже VIS (`b > VIS`) невидимы: они всё равно
  лежат точно под задним слотом. Улетевшая на границе бита телепортируется именно туда —
  под карточку с тем же трансформом, поэтому шов пиксельно нулевой.
- **Два тайминга в одном бите**: колода — `state.easeFn` (по умолчанию кастомный
  `bez:[.4,0,.1,1]` через тот же `setCustomBez`, что у Push Row), dur 1.65 с, hold 0.3;
  вылет — своя кривая `exitBez` (.42,0,.58,1), `exitDur` 0.93 с, поворот `exitRot` 32°
  вокруг `exitPivot`, масштаб `1 + exitGrow·p²`. Кривая вылета НЕ идёт за чипами
  пользователя: ease-out/snappy на колоде читаются как характер сдвига, а вылет с
  перелётом маятника выглядел бы как ошибка.
- **Хвост вылета** `exitTail:.35`: после 0.93 с угол продолжает линейно расти ещё на
  35 % свинга до конца бита (−32° → −43°). Без него на 16:9 угол карточки на p=1 всё ещё
  на 0.16 H внутри кадра (в референсе он тоже виден), а под наклоном/Card Size 1.6 карточка
  была бы в кадре в момент телепорта на задний слот. Считано: 3:4 / 9:16 / 1:1 — вне кадра
  уже на p=1, 16:9 — вне кадра к концу бита (−0.99 H при крае −0.89 H).
- **Spacing живой**: масштабирует только шаг угла (10°·spacing), пивоты и размер стоят.
- **Петля** `cyc·N0` при паддинге n до кратного N0 (как у Push Stack — не экспортировать
  одно и то же дважды); если есть per-card override (`slotOverrides`), петля `cyc·n`.
- `corner:1` (= 3.75 % стороны по формуле `corner/12·0.45`), референс ≈ 3 %; `corner:3`
  дало бы 11 % — заметно круглее оригинала.
- Direction зеркалит по x (позиции и знаки углов).

### Как сделано — движок `gridJump`
Ближайшие движки: геометрия из `scrollCols` (колонки-ленты с wrap-ом, живой
pitch), механика «шаг + покой + волна + своя кривая» из `pushFeed`. Ни один не
подошёл как есть (scrollCols линейный и бесконечный, соседние колонки в разные
стороны; pushFeed одноленточный и шагает на одну карточку) — новый движок,
чужой код не тронут.

- **Геометрия.** `CARD = 0.259·min(W, 0.75·H)` — при 3:4 (и любом более узком
  кадре) это ровно 0.259 W, при широких кадрах карточка привязана к высоте, чтобы
  16:9 давал БОЛЬШЕ колонок, а не четыре карточки во весь экран. Зазор
  `G0 = 0.143·CARD`, ячейка 1:1 (`texAt(slot, 1)`), corner 0.
  Колонок `ceil((W+G0)/pitch)+4` — сколько нужно, чтобы покрыть кадр в покое,
  плюс по две за кадром с каждой стороны (Rotate Y 45° видит за край кадра).
  Чётность сохраняется → при 3:4 их 8, центр кадра на зазоре, как в референсе.
  Сетка центрирована и выходит за края.
- **Дискретный шаг.** Бит `cyc = dur + hold = 4.0 с`. Ход за бит `S = 6` рядов
  (`P.step`); прогресс колонки `p = Σ_k ease((m0 + k·cyc − delay_c)/dur)` по
  предыдущим битам — хвост поздней колонки (delay + dur > cyc) переезжает
  границу бита непрерывно, без снапа. Не клампится к 1 → Snappy даёт
  честный перелёт и возврат. Позиция `y = (j·pitch − p·S·pitch) mod span`,
  wrap далеко за кадром.
- **Волна.** `delay_c = 0.11·c` слева направо (`P.stagger`), dur общая; при
  `state.dir < 0` — вниз и волна справа налево (зеркально).
- **Петля один бит без шва при любом N.** Картинка ряда j колонки c —
  `slot = c·OFF + (j mod S)`: паттерн колонки повторяется каждые S рядов,
  поэтому после сдвига на S рядов кадр пиксельно тот же. Число баканых рядов
  `perCol` = (ряды на покрытие кадра при zero-gap + 8 буферных для наклона),
  округлённое ВВЕРХ до кратного S — тогда wrap меша (ряд perCol−1 → ряд 0)
  продолжает паттерн. Правила против дублей: пока `N | (S−1)` — `S++` (иначе
  на стыке цикла две одинаковые карточки подряд; N=5 → S=7);
  `OFF = S`, а если `N | S` — `S+1` (иначе все колонки одинаковые).
  Клик-замена по слоту меняет картинку сразу во всех повторах слота —
  это и нужно, иначе шов.
- **Spacing живой** (LIVE_SPACE): `G = G0·spacing`, меняется только зазор,
  карточки жёсткие; pitch/span/jump считаются в update(). Fade — FLAT_ROT_FADE
  (плоско в покое, глубина только под наклоном).
- **Наклон.** Рисуем ближние к камере карточки поверх (Card Size > 1 их
  перекрывает): Rotate X > 0 уводит камеру ВНИЗ (ближе нижние ряды), Rotate Y > 0
  — вправо; `renderOrder` от непрерывной позиции + крошечный стабильный
  tiebreak, плюс та же мелкая z-лестница `0.05·CARD·tiltR`, что у Push Row.
  В покое всё плоско, z = 0.
- **Кривая.** Пресет несёт `bez:[.5,0,0,1]` (rms 0.006 против референса; Push
  Row-ская [.4,0,.1,1] — 0.022, Smooth > 0.2). Чипы Smooth/Ease Out/Snappy.
  `dur 3.7, hold 0.3` — хвост выбега (6 → 0 px/кадр за последние 36 кадров)
  оставлен целиком, укорачивать dur нельзя без потери характера.

### Тупики / заметки
- Первая мысль — ход за бит = perCol (весь бакеный столбец) — даёт шов

### Fan Deck: «топорно, карточка нелогично заходит на следующую»
